# miniagent 项目说明书

> 如何配置 · 如何使用 · 如何扩展
>
> 本文档面向部署者和二次开发者；各阶段实现细节见 `mkd/` 目录下的总结文档。

miniagent 是不使用 langchain 的小型 Agent 实现：基于 OpenAI SDK 接入 DeepSeek，提供**可视化 Web 对话页**（实时展示思考/工具调用/结果）、**工具调用**（单步函数 + 短固定工作流，由 LLM 编排）、**Prompt 角色管理**，以及**对外异步服务接口**。

---

## 一、如何配置

### 1.1 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.12 |
| 操作系统 | Windows / macOS / Linux（本文以 Windows 为例） |
| 数据库 | 默认无需额外数据库（SQLite 内置于标准库）；连 MySQL/PostgreSQL 需另装驱动，见 3.5 |

### 1.2 安装依赖

```powershell
# 项目根目录执行
python -m venv miniagt
miniagt\Scripts\activate
pip install -r requirements.txt
```

依赖分组说明：Agent 核心（`openai`/`SQLAlchemy`）、Web 服务（`fastapi`/`uvicorn`/`websockets`）、客户端测试（`websocket-client`）、CdpTools（`PyQt5` 等，不用 CdpTools 可不装）。

### 1.3 配置密钥

复制 `agent/.env.example` 为 `agent/.env`，填入真实值：

```ini
API_KEY=sk-xxxxxxxxxxxxxxxx
DS_URL=https://api.deepseek.com
```

| 键 | 说明 |
|---|---|
| `API_KEY` | DeepSeek 的 API Key |
| `DS_URL` | API Base URL，官方为 `https://api.deepseek.com` |

**注意**

- `agent/.env` 已被 `.gitignore` 忽略，**不要提交**；
- 代码中 `load_dotenv()` 显式指向 `agent/.env`（`agent/llm/agent.py`），因此**从任意工作目录启动均可读到密钥**；
- 默认模型为 `deepseek-flash`，开启思考模式（`extra_body={"thinking": {"type": "enabled"}}`），如需更换模型改 `agent/llm/agent.py` 中的 `MODEL` 常量。

## 二、如何使用

### 2.1 启动服务

```powershell
python main.py
```

启动后访问 <http://127.0.0.1:8000>。一个进程同时提供：

| 入口 | 说明 |
|---|---|
| `GET /` | 可视化聊天网页 |
| `WS /ws/chat` | 聊天长连接（网页内部使用，也可编程接入） |
| `GET /roles` | 可用角色列表 |
| `GET /workflows` | 已注册工作流列表 |
| `POST /api/v1/chat` | 提交异步对话任务 |
| `GET /api/v1/task/{task_id}` | 查询任务状态与结果 |

### 2.2 Web 对话页

- 底部输入框输入消息回车发送（Enter 发送、Shift+Enter 换行，中文输入法候选确认不会误发）；
- 右上角**角色下拉**切换提示词角色（切换会重置当前会话历史，因为 system 提示词不同）；
- 右侧**执行时间线侧边栏**按轮次展示 agent 每一步：紫色 **思考**（流式增量、单节点聚合）、蓝色 **调用**（工具名 + 参数）、绿色 **结果**（工具返回，超长截断）、黑色 **回答**（摘要）；顶栏"时间线"按钮可折叠侧边栏；
- 服务未连接时发送按钮禁用并显示"重连中…"，断线自动重连（2 秒间隔）。

### 2.3 对外异步接口

```powershell
# 提交任务，立即返回 task_id
curl -X POST http://127.0.0.1:8000/api/v1/chat `
     -H "Content-Type: application/json" `
     -d '{"message": "1+1 等于几", "role": "default"}'
# → {"task_id": "a1b2...", "status": "queued"}

# 轮询结果（status: queued/running/succeeded/failed）
curl http://127.0.0.1:8000/api/v1/task/<task_id>

# 携带全部执行步骤（分析 agent 决策用）
curl "http://127.0.0.1:8000/api/v1/task/<task_id>?include_steps=true"
```

步骤结构（`AgentStep`）：

```json
{"type": "reasoning|tool_call|tool_result|answer",
 "content": "", "tool_name": "", "tool_args": {}, "tool_result": ""}
```

### 2.4 WebSocket 协议

连接 `ws://127.0.0.1:8000/ws/chat`，双向 JSON：

| 方向 | 格式 |
|---|---|
| 发送 | `{"message": "用户输入", "role": "default"}` |
| 接收·步骤 | `{"type": "step", "step": {…AgentStep…}}` |
| 接收·完成 | `{"type": "done", "content": "最终回答"}` |
| 接收·出错 | `{"type": "error", "message": "…"}` |

同一连接、同一角色下保留多轮上下文；`reasoning` 步骤按流式分片多条推送，前端需追加渲染。

### 2.5 作为 Python 库使用

```python
from agent.llm.agent import create_llm, system_msg, user_msg
from agent.llm.agent_loop import run_agent
from agent.agent_tools.build_tools import get_tools

client = create_llm()
messages = [system_msg(role="data_analyst"), user_msg("查询 sqlite:///demo.db 的 users 表")]

def show(step):
    print(f"[{step.type}]", step.content or step.tool_name or "")

answer = run_agent(client, messages, tools=get_tools(), step_callback=show)
```

### 2.6 运行测试

```powershell
python -m unittest tests.test_phase2_3 -v   # DB/工作流/意图/Prompt 单元测试（无需密钥）
python tests/test_phase4_6_smoke.py         # 服务冒烟（自动起停，无需密钥）
```

## 三、如何扩展

### 3.1 新增单步工具（LLM 可编排）

在 `agent/agent_tools/` 或 `agent/dbase/` 新建模块，用 `@tool` 装饰即自动生成 Schema 并注册：

```python
# agent/agent_tools/weather.py
from .build_tools import tool

@tool(description="查询城市天气",
      param_descriptions={"city": "城市名，例如 北京"})
def get_weather(city: str) -> str:
    return f"{city} 晴，25 度"
```

然后在 `agent/llm/agent_loop.py` 顶部导入一次（导入即注册）：

```python
from ..agent_tools import weather  # noqa: F401
```

规则：

- 参数注解用基础类型（`str/int/float/bool/list/dict`），当前 Schema 生成器不支持 `Optional` 等复杂注解；
- 返回 `str`；数据量大时自行截断（LLM 上下文有限）；
- **安全**：绝不用输入拼接 SQL/命令；表名字段名先校验白名单，值走参数绑定（参考 `dbase/db_query.py`）。

### 3.2 新增短固定工作流

在 `agent/workflows/` 写模块，用 `@workflow` 装饰模块级函数：

```python
# agent/workflows/my_flow.py
from .registry import workflow

@workflow(description="查询用户表并统计年龄分布")
def user_age_stats(db_url: str) -> dict:
    ...  # 固定步骤：可调用 query_database 等既有函数
```

在 `agent/workflows/__init__.py` 中加一行 `from . import my_flow  # noqa: F401` 完成注册。之后 `run_workflow("user_age_stats", db_url=...)` 可执行，`GET /workflows` 可见。CdpTools 的 `Browser/Tab/Element` 同样可作为工作流步骤接入（工作流是普通 Python 函数）。

### 3.3 接入意图识别（路由到工作流）

`agent/llm/intent.py` 已定义接口，替换占位实现即可：

```python
def detect_intent(text: str) -> IntentResult:
    # 用小模型分类：给定 list_workflows() 的名称+描述作候选
    # 返回 IntentResult(intent="...", workflow="user_age_stats",
    #                   confidence=0.92, reason="...")
```

路由方式（伪码）：`detect_intent(text) → confidence 达阈值且 workflow 非空 → run_workflow(workflow)`，否则走 `run_agent` 通用对话。

### 3.4 新增 Prompt 角色

两种方式：

- 直接编辑 `agent/llm/prompts.py` 的 `PROMPTS` 字典；
- 运行时注册：`register_prompt("translator", "你是一名专业翻译…")`。

随后 `system_msg(role="translator")`、网页角色下拉（`GET /roles`）自动生效。自定义 role 提交到 `/api/v1/chat` 同样可用。

### 3.5 接入不同数据库

`query_database` 的 `db_url` 直接决定数据库类型，无需改代码：

| 数据库 | db_url 示例 | 额外依赖 |
|---|---|---|
| SQLite | `sqlite:///./test.db` | 无 |
| MySQL | `mysql+pymysql://user:pwd@host:3306/dbname` | `PyMySQL`（已在依赖中） |
| PostgreSQL | `postgresql+psycopg2://user:pwd@host/dbname` | `psycopg2-binary` |

安全边界：工具只支持**查询**（select + 等值过滤 + limit ≤ 200），表/字段先经反射元数据校验，过滤值参数绑定，不会执行写操作。

### 3.6 前端扩展

步骤渲染集中在 `agent/web/static/app.js` 的 `renderStep()`：新增 `AgentStep` 类型或想按工具名定制卡片，在该函数里按 `step.type` / `step.tool_name` 分支即可，无需改服务端。样式在 `style.css` 的 `.step.*` 区块。

### 3.7 目录速查

```
agent/
├── agent_tools/   # 单步工具（@tool 注册）
├── dbase/         # 数据库通用工具
├── workflows/     # 短固定工作流（@workflow 注册）
├── llm/           # 客户端、run_agent 循环、prompt 角色、意图接口
```

## 四、常见问题

**启动报 `The api_key client option must be set`**：`agent/.env` 不存在或未填 `API_KEY`，按 1.3 配置。

**工具查询失败 `表 xxx 不存在或无法访问`**：db_url 写错或表名不正确；SQLite 路径建议用绝对路径。

**网页无法连接（灰点）**：服务未启动或被防火墙拦截；确认 `python main.py` 正常且访问的是 `127.0.0.1:8000`。

**WS 握手 404、页面无法发送**：`websockets` 包未安装时 uvicorn 的 `auto` 探测会静默禁用 WebSocket。`main.py` 已显式指定 `ws="websockets-sansio"`，此时启动会直接报错——按 1.2 重装依赖即可；不要绕过 `main.py` 用裸 uvicorn 启动。

**异步任务一直 `running`**：模型响应慢或工具执行阻塞，等 `failed`/`succeeded` 终态；也可用 `include_steps=true` 看卡在哪一步。

**GBK 控制台打印 emoji 报错**：Windows 终端编码问题，与功能无关；可设 `$env:PYTHONIOENCODING="utf-8"`。
